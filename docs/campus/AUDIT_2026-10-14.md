# System audit and product analysis — 2026-10-14

Scope: the Forge learner app, Forge admin, Forge API, Campus API and the college portal, plus the live Supabase
database (`wxrxnqhjkwlxvmaopvlv`). Method: code review, the test suites, browser checks of every learner page and
every portal page at desktop / tablet / phone width, and read-only queries on live.

## 1. Verdict

The software is ready for a **paid pilot with one or two colleges**; it is **not yet ready to sell at scale**. What
blocks selling is not features — 506 of the 1,898 checklist items are done, and the ones colleges buy on (tests,
proctoring, results, placement drives, college content, community) work end to end — it is four things around the
software:

1. **Content.** Live has 8 practice problems, 0 test series, 0 test-series questions, 6 courses (183 quiz questions).
   A college buys a question bank and mock tests on day one.
2. **Production operations.** Only the DB tests run in CI; there is no deployment config in the repo; the Campus API,
   the portal and wildcard college subdomains (`<slug>.forge.com`) are not deployed; email (Resend) is not configured,
   so invitations, password resets and result notices don't send; no exam-day load test has been run.
3. **College commercial path.** Colleges can be created, given seats and licences, suspended — but there is no order
   form, institutional GST invoice or per-student price yet.
4. **Legal and privacy.** Device fingerprints and IP addresses are personal data under India's DPDP Act 2023: a
   privacy notice, a retention period and a data processing agreement for colleges are needed before selling.

Live usage today: 12 users, 0 colleges, 0 captured payments.

## 3. Security posture

**Good:** RLS on every table, server-only tables with no client grants, college isolation proven by SQL suites in CI,
bans enforced by both APIs, maintenance and kill switches, rate limits on auth, OTP, writes, submissions and AI,
webhook signatures, signed sessions with revocation, admin audit logs, keys never sent to the browser.

**Remaining risks, in order:**

1. **Owner actions:** rotate the keys that were ever shared in chats; enable leaked-password protection in Supabase
   Auth; set `FRONTEND_URL`, `RESEND_*`, Razorpay live keys and `CAMPUS_BASE_DOMAIN` in production.
2. **Edge protection:** no CDN/WAF in front of the APIs. Put Cloudflare (or the host's equivalent) in front for DDoS
   and bot protection; the in-app flood ceiling is a backstop, not a shield.
3. **AI provider keys are stored in plain text** in `system_settings` (masked in the admin). Move them to Supabase
   Vault or the host's secret store.
4. **Google sign-up bypasses "pause sign-ups"** (it goes straight to Supabase Auth). Use a Supabase auth hook if
   sign-ups ever need to be closed hard.
5. **Dependencies:** `express-rate-limit` 8.7.1 (fix released 8 days ago — take it after two weeks), Tailwind 3 build
   chain, Sentry's glob dependency. None ships to browsers.
6. **Backups:** confirm the Supabase plan has point-in-time recovery before colleges store exam results.

## 4. Anti-cheating: what it can and can't do

Now: full-screen lockdown, tab/window/full-screen exits, copy/paste/right-click blocked, warning-then-violation,
auto-submit at a limit, device binding, second-screen detection (Chrome/Edge), developer-tools detection,
screenshot keys, large-insert detection, shuffled questions and options, paper versions, question pools, timed
sections, live invigilation board, incident reviews, integrity report (shared devices and networks between students).

Browser-based proctoring cannot see a phone on the desk or a person in the room. The next steps, if colleges ask:
optional webcam snapshots at random times (consented, stored per college), code-similarity checks between
students' coding answers, and answer-timing analysis (correct answers far faster than reading time).

## 5. Product analysis — what's critical before selling

**Critical (before the first paid college):**
- Question bank and mock tests: ~300 aptitude, ~150 coding problems with tests, 10+ full mocks (W5 drafts).
- Deploy Campus API + portal, wildcard DNS/TLS for college subdomains, email delivery, monitoring alerts.
- Exam-day load test: 300–500 students starting the same test in one minute, including coding judging.
- College commercial path: price per student per year, order form, GST invoice for institutions.
- Privacy notice, retention policy (e.g. device/IP records 180 days), college DPA, terms.
- A TPO onboarding guide (roster upload, first test, live board, results).

**Important (first quarter after launch):** Google Workspace / Microsoft SSO for colleges; webcam proctoring
option; code plagiarism; placement reports export for NAAC/NIRF; a status page; in-app support chat.

**Already more than enough (don't build more now):** gamification depth, apprenticeship programs, build
challenges, referral tiers, experiments, admin tooling breadth, AI features beyond the mentor. These help retention
later; they don't decide a college purchase.

**Positioning:** one college workspace that combines learning (courses, practice), assessment (proctored tests with
integrity reporting), placement drives and a student community, under the college's own subdomain. Pricing and
competitor comparisons are hypotheses to test in pilot conversations, not facts in this audit.
